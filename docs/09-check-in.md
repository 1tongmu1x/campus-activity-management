# 活动签到

已发布的活动可以在开始前 30 分钟至结束前开启签到。管理员在活动列表点「签到」，再点「开启签到」，把窗口中的二维码展示给到场同学。参与者扫码后输入报名手机号即可签到。

- 同一条报名记录只能签到一次。未报名或已取消报名的手机号不能签到。
- 管理员可在签到窗口刷新人数，也可在「报名名单」里查看每个人的状态和时间。
- 点击「结束签到」或修改活动的开始、结束时间，旧二维码会失效。再次开启时会生成新二维码，已有签到记录会保留。活动结束后系统停止接收签到。
- 使用临时公网演示时，签到链接和报名链接使用同一个临时域名。手机扫码前，请保持后端与演示脚本运行。每次重启临时隧道，都要重新展示当前二维码。

## 演示步骤

重启后端和临时公网演示脚本，让后端自动执行 Flyway 的 V3 迁移，并让前端重新构建。新建一条模拟活动，设为约 10 分钟后开始、1 小时后结束，报名截止设成约 5 分钟后。发布后先提交一条模拟报名，再开启签到。手机用移动数据扫描签到二维码，填同一个测试手机号。管理员打开报名名单，查看「已签到」和时间。可以再试一次重复提交，最后关闭签到并刷新旧链接。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/activities/{id}/check-in` | 读取状态、可开启时间、签到结束时间和人数 |
| POST | `/api/admin/activities/{id}/check-in/open` | 开启签到，返回当前二维码编号 |
| POST | `/api/admin/activities/{id}/check-in/close` | 关闭签到，使当前二维码失效 |
| GET | `/api/public/check-in/{code}` | 展示活动名、地点和签到结束时间 |
| POST | `/api/public/check-in/{code}` | 提交 JSON `{"phone":"19900000001"}`，成功返回 201 |

公开签到复用 `/api/public/csrf`。后台名单接口新增 `checkedInAt`，未签到时为 `null`。基础签到使用活动窗口内有效的二维码和报名手机号核对；需要核实人员是否到场时，工作人员可按名单复核。
