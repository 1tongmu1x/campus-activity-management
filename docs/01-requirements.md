# 需求基线（v0.1）

## 1. 角色

| 角色 | 是否需要账号 | 主要权限 |
| --- | --- | --- |
| 活动管理员 | 是 | 管理活动、报名、签到和统计数据 |
| 普通参与者 | 否 | 查看公开活动、报名、签到 |

## 2. 核心业务流程

1. 管理员创建活动，初始状态为“草稿”。
2. 管理员编辑并发布活动，系统提供公开活动详情链接和报名二维码。
3. 参与者填写姓名、手机号、学院后提交报名。
4. 系统校验活动状态、报名时间、人数上限和手机号重复报名。
5. 活动现场，参与者扫描签到二维码并输入手机号完成签到。
6. 管理员查看报名名单、签到名单和人数统计。

## 3. 功能验收标准

### 3.1 活动生命周期

- 管理员可创建活动，字段至少包括名称、类型、简介、开始/结束时间、地点、报名截止时间、人数上限。
- 可选字段：直播链接、附件。
- 管理员可以编辑、删除、发布活动；编辑不得删除已有报名记录。
- 支持按活动类型、状态、时间范围筛选。
- 页面显示状态：草稿、已发布/报名中、报名截止、已结束。

### 3.2 公开报名

- 参与者不注册、不登录即可访问公开活动页。
- 报名资料包含姓名、手机号、学院。
- 系统必须拒绝未发布、已截止、已满员、已结束和同手机号重复报名。
- 报名成功或失败均给出清晰提示。

### 3.3 签到

- 基础版：扫描活动签到二维码后输入手机号签到。
- 参与者必须已报名且未签到；不满足条件时显示原因。
- 加分版：短时有效的动态二维码、定位校验等防代签能力。

## 4. 本期边界

- 第一版不提供普通用户账户体系、支付、消息推送或多校区权限体系。
- 管理员认证使用账号密码；密码不以明文存储。
- 个人信息仅服务于报名与签到，不在公开页面显示完整手机号。
